System specification // 02

An agent loop with an economic control plane.

The architecture separates willingness to reason from authority to act. Compute, money, secrets, deployment, and destructive operations remain bounded and auditable.

System map
Six layersJob lifecycleModel routerLedgerGovernance

Six bounded layers

01 // Interface

Human coding agent

Repository search, edits, shell, tests, browser, git, and clear approval boundaries.

02 // Marketplace

Paid machine services

Narrow requests with deterministic inputs, acceptance tests, prices, and service-level limits.

03 // Orchestrator

Job state machine

Quotes, reserves, execution, verification, settlement, retries, refunds, and dispute records.

04 // Intelligence

Economic model router

Selects a model and token budget against expected margin and probability of success.

05 // Treasury

Double-entry ledger

Every reserve, cost, payment, refund, and subsidy creates balanced immutable entries.

06 // Execution

Disposable sandboxes

Per-job filesystem, network, CPU, time, and secret limits with complete artifact capture.

The router buys intelligence

Routing is not merely easy task → small model. The router estimates the value of a correct result, confidence by model, latency, context cost, and remaining reserve.

budget(job) = min(customer price × risk fraction, treasury policy cap)
route = highest expected quality with positive expected contribution
fallback = only if remaining budget ≥ next-attempt cost + settlement reserve

Money is never a mutable balance field

The treasury balance is derived from entries. Jobs cannot directly edit it. Idempotency keys prevent double settlement, database transactions couple state changes to entries, and a reconciliation worker compares the ledger to external payment rails.
