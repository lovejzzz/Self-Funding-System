The agent may propose work and spending. A legal operator, deterministic policy engine, isolated signer, external payment rail, and reconciled ledger decide what money exists and whether it can move.

Six bounded layers

01 // Interface

Human coding agent

Repository search, edits, shell, tests, browser, git, and clear approval boundaries.

02 // Marketplace

Paid machine services

Narrow requests with deterministic inputs, acceptance tests, prices, and service-level limits.

03 // Orchestrator

Job and money state machine

Tracks quotes, payment finality, internal reserves, execution, verification, revenue recognition, refunds, and disputes as separate states.

04 // Policy

Authority before intelligence

The model proposes. Deterministic limits decide whether the payee, purpose, amount, timing, and remaining reserve permit an action.

05 // Treasury

Custody, signer, and ledger

The legal operator holds the external account. Signing credentials remain isolated. An append-only, tamper-evident journal records every movement and reconciles it to the rail.

06 // Execution

Disposable sandboxes

Per-job filesystem, network, CPU, time, and secret limits with complete artifact capture.

Stripe enables delegation, not personhood

SUPPORTED — Stripe does not make the agent a legal person or independent merchant. A verified operator is the Stripe User and merchant of record. The operator owns the funds and remains responsible for the customer contract, tax, refunds, disputes, and account activity; the agent performs only authorized software actions.

ParticipantIdentity and responsibilityPermitted role
OperatorVerified Stripe User and first-version merchant of recordOwns accounts, policy, customer obligations, and final responsibility
AgentElectronic executor attributable to the operatorQuotes work and proposes or performs narrowly authorized API actions

Stripe solves the operational handoff: software can run payments for a verified operator. It does not solve identity by giving the software its own Stripe account.

The router buys intelligence

Routing is not merely easy task → small model. The router estimates the value of a correct result, confidence by model, latency, context cost, and remaining reserve.

budget(job) = min(customer price × risk fraction, treasury policy cap)
route = highest expected quality with positive expected contribution
fallback = only if remaining budget ≥ next-attempt cost + settlement reserve

Money is a reconciled claim, not a mutable balance field

The external account or wallet proves custody; the internal ledger explains purpose and availability. Jobs cannot edit either balance. Every receipt, reservation, provider charge, refund, transfer, and policy allocation is append-only, balanced, idempotent, and checked against independent rail data.

Build the smallest credible money loop.

One operator, one receiving rail, one restricted operating wallet, one service, one provider, one refund path, and daily reconciliation before pursuing treasury growth.
