V0.1 scope

Build
  • One endpoint: generate tests for one function
  • Prepaid fixed quote
  • Hard model and execution budget
  • Automated acceptance checks
  • Double-entry financial ledger
  • Daily solvency report
Do not build
  • General autonomous job hunting
  • Open-ended production deployment
  • Self-modification
  • Unbounded wallet authority
  • Multiple services before margin proof
  • A new foundation model

Core schema

Postgres // minimum durable state
jobs(id, service, state, input_hash, quoted_price,
     cost_limit, accepted_at, completed_at)

attempts(id, job_id, model, token_limit, model_cost,
         sandbox_cost, status, artifact_hash)

accounts(id, code, currency, kind)
transactions(id, idempotency_key, job_id, created_at)
entries(id, transaction_id, account_id, amount)

policies(id, version, document, active_from)
Store money as integer minor units. Derive balances from entries. Couple every job-state transition and ledger booking in one database transaction.

The critical request path

01

Quote

Validate the request, hash canonical input, estimate model plus sandbox cost, and return a short-lived fixed price.

POST /v1/quotes
02

Fund

Verify payment authorization, create a pending revenue transaction, and reserve the maximum permitted job cost.

POST /v1/jobs
03

Run

Worker claims the job, chooses a model within budget, executes in a fresh sandbox, and records exact usage.

worker.claim → router → sandbox
04

Verify and settle

Acceptance tests must pass before settlement. Failed work releases unused reserve and follows the refund policy.

verify → book costs → settle revenue

The first ten commits

  1. Initialize workspace, formatting, type checks, tests, and CI.
  2. Add Postgres migrations and typed identifiers.
  3. Implement balanced ledger transactions and invariant tests.
  4. Add quote creation with signed expiry and input hashing.
  5. Add payment adapter interface and local fake rail.
  6. Add job state machine with idempotent transitions.
  7. Add model router with hard per-job budget.
  8. Add disposable sandbox adapter and artifact hashing.
  9. Add verifier, settlement, refund, and reconciliation worker.
  10. Add the public solvency dashboard and $20 experiment fixture.

Definition of done

  • A duplicate request cannot double-charge or double-settle.
  • A crashed worker can safely resume or release the job.
  • A job can never exceed its recorded cost ceiling.
  • Every successful result has verifiable artifacts.
  • Ledger totals reconcile to the payment rail.
  • Ten consecutive accepted jobs produce positive contribution.

Then run the finite-capital experiment.

Do not add another feature until the first service proves or disproves positive unit economics.
